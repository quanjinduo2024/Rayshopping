# Rayshopping 购物平台开发实施方案

## Context

Rayshopping 是一个基于微服务架构的简易购物平台，采用 React + Ant Design 前端与 FastAPI 微服务后端架构。项目处于初始阶段，仅有 PRD 文档和 Git 仓库。本方案将指导整个项目从脚手架搭建到功能实现的完整开发流程。

## 开发流程规范

### Git 提交规范（中文）

```
<type>(<scope>): <中文描述>

type 类型：
- feat: 新功能
- fix: 修复 bug
- docs: 文档更新
- style: 代码格式调整
- refactor: 重构
- test: 测试相关
- chore: 构建/工具相关

示例：
feat(user): 添加用户注册接口
fix(shop): 修复购物车数量计算错误
test(user): 添加用户登录单元测试
```

### 分支策略

```
main (主分支，稳定)
  └── develop (开发分支)
       ├── feature/user-module (成员A)
       └── feature/shop-module (成员B)
```

### 测试左移流程

```
开发任务开始
    ↓
编写接口契约（API 文档）
    ↓
编写单元测试（TDD - 红→绿→重构）
    ↓
实现业务代码
    ↓
运行单元测试 → 不通过则修复
    ↓
本地集成测试
    ↓
提交代码 + PR
    ↓
代码评审
    ↓
合并到 develop
```

### 后端测试（pytest）

测试文件位置：`user-service/tests/` 和 `shop-service/tests/`

关键 Fixtures：
- `client`: FastAPI TestClient
- `db_session`: 内存 SQLite 数据库会话

测试命令：`pytest --cov=app --cov-fail-under=80`

### 前端测试（Vitest + React Testing Library）

测试文件位置：`frontend/tests/`

测试命令：`npm test` 或 `npm run test:coverage`

## 关键技术实现

### user-service (端口 8001)

- JWT 认证中间件
- 密码哈希（bcrypt）
- 用户校验接口：`GET /user/exist?user_id=xxx`

### shop-service (端口 8002)

- 通过 HTTP 客户端调用 user-service 校验用户
- 订单创建时的事务处理（库存扣减 + 订单生成）
- AI 推荐功能延后实现

### 前端（端口 3000）

- React Router 6 路由管理
- Redux Toolkit 状态管理（user + cart）
- Axios 拦截器自动添加 JWT Token

## 验证步骤

1. 启动 user-service: `cd user-service && uvicorn app.main:app --reload --port 8001`
2. 启动 shop-service: `cd shop-service && uvicorn app.main:app --reload --port 8002`
3. 启动前端: `cd frontend && npm run dev`
4. 访问 http://localhost:3000 验证完整流程

## 约束与约定

1. **提交信息必须使用中文**
2. **测试左移：先写测试，再实现功能**
3. **单元测试覆盖率不低于 80%**
4. **AI 推荐功能延后实现**
5. **双人协作：PR 必须经过另一人审核才能合并**
